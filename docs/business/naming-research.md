# Vandrekalender: Naming Research v2 and DMF Call Prep

*Research summary, 2 September 2026. Builds on `Vandrekalender_CompetitiveLandscape_v1.md`.*

## 1. Where things stand

Finn Nielsen (formand, Dansk Motions Forbund) has replied to the outreach email. Two things in his short answer matter. First, "der er en ny på vej med samme navn": DMF is not retiring Vandrekalenderen, they are rebuilding it under the same name, presumably inside vandredanmark.dk. Second, "Vi har haft vandrekalenderen siden 1974": the name predates the internet for them, and this line is a friendly but clear ownership marker. The tone is warm and he wants the call. There is no legal threat and nothing suggests one is coming.

Decision taken by Petya on 2 September 2026: rename, and pick a descriptive Danish name. The rest of this document is about doing that once, properly, and about making the call with Finn productive.

## 2. Why renaming is the right call (short version, so it is on record)

Neither "vandrekalender" nor "vandrekalenderen" is a registered trademark. A fresh TMview search on 2 September 2026 across the Danish office (DKPTO), EUIPO and WIPO for every mark containing "vandre" returned 19 hits, all unrelated (Danhostel's "vandrerhjem" marks, a Dutch clothing brand "Vandrelaar", an Italian "VANDRE'" and so on). A search for "vandring" returned only two marks, "St. Enders" and "HÆRVEJSMARCHEN". So no registration blocks anyone from using the word.

That is not the whole picture, though. Danish law also protects a name that has been used consistently in trade for a long time even without registration (Varemærkeloven and Markedsføringsloven both recognise rights established through use), and the Danish domain complaints board (Klagenævnet for Domænenavne) decides cases under the "god domænenavnsskik" rule in Domæneloven § 25. For generic or descriptive words the board balances first-come-first-served against whether a registrant is using the name actively and in line with its meaning, and it does weigh long, established use by a complainant. Petya's use is real and active, which is the strongest thing in her favour, and she would have a defensible case. But "defensible" is the wrong bar for a project whose whole point is to be the friendly, open hub for Danish walking. Sharing a name with a 52-year-old federation calendar means permanently sharing Google results with it (Google already blends the two queries and ranks DMF first), permanently confusing organisers who hear "vandrekalender" and land on the wrong site, and permanently having a reason for DMF to see the project as a rival rather than a partner. A rename removes all three at once, and doing it now, with two organic users and around 100 clicks a quarter, is about as cheap as it will ever be.

## 3. What was checked this round, and how

The previous round checked one candidate. This round applied the same checks to a wide field so the choice does not have to be revisited.

Availability was checked in two passes. First, a DNS name-server lookup on 89 candidate .dk names (a domain with no name servers at all is almost always unregistered; every known live site in the list correctly showed as taken, which validates the method). Then the shortlist was confirmed one by one on punktum.dk, the official .dk registry, using their live domain search, with vandreture.dk (known to be taken) as a control.

Existing use was checked with web searches for each shortlisted name and its natural spoken form, looking for companies, associations, Facebook pages, blogs or products already using it.

Trademarks were checked in TMview (DKPTO, EUIPO, WIPO) for "vandre" and "vandring" as substrings, which covers every candidate below.

Neighbouring domains were checked too, because the current problem is exactly a neighbour problem: vandrekalender vs vandrekalenderen. For each finalist the definite form, the singular form and the hyphenated form were checked, so the same trap cannot repeat.

## 5. Recommendation

Primary: **allevandreture.dk**, brand written "Alle Vandreture". It passes every check, it is the name that best encodes what makes the project different (everyone's tours, one place), and it uses the word Danes actually type into Google. The tagline carries the calendar meaning that the name itself lacks, for example "Alle vandreture i Danmark, samlet i én kalender" or shorter "Find din næste vandretur".

Decision (2 Sept 2026): Petya chose allevandreture.dk. Register two names: allevandreture.dk (main) and allevandreturene.dk (the definite form, the same kind of neighbour that vandrekalenderen is to vandrekalender; redirect it to the main domain). The singular allevandretur.dk is grammatically wrong in Danish and not worth registering. A .dk domain costs roughly 50 to 150 DKK a year per name through a registrar, so the defensive set is cheap. Punktum.dk moved to a registrar-based administration model on 1 July 2026 (their front page currently leads with it), so the simplest path is to register through Nordicway, the current host, or any registrar on punktum.dk's list, and have all names in one place.

Backup if Petya prefers a more brand-like feel: **vandreoverblik.dk** with vandreoverblikket.dk alongside. It is equally clean. It just does less SEO work on its own.

Keep vandrekalender.dk for at least 12 months as a permanent redirect to the new name so that the existing Google equity, the two organisers' links, and the kontakt@ mailbox all carry over. Whether to eventually hand vandrekalender.dk to DMF is a separate decision for later, and a card Petya can choose to play in the relationship, not something to offer on the first call.

One more registration to make at the same time: the Facebook page name and the Instagram handle "allevandreture", both of which had no results in search.

## 6. A landscape finding that changes the competitor picture

The search for existing use surfaced something the v1 landscape document missed: **Dansk Vandrelaug (DVL)**, dvl.dk. DVL is Denmark's national ramblers' association with 21 regional branches, and dvl.dk/vandreture is a live tour search with date and distance filters and around 58 pages of upcoming guided walks. It is bigger, more modern and more relevant to Vandrekalender's scope than DMF's calendar, and it is not in the scraping sources list either. Two implications. First, "Danske Vandreture" as a brand would sit uncomfortably close to Dansk Vandrelaug, which is one reason it is not recommended above. Second, DVL should be added to `Vandrekalender_ScrapingSources_v2.docx` as a priority source, and possibly approached the same way as DMF once the name is settled.

## 7. The call with Finn

### What Petya wants out of it

A friendly relationship with DMF, a green light to list their walks (with attribution and a link back), a sense of whether there is paid or freelance work in their platform rebuild, and to leave Finn with the impression of a generous, competent person, not a competitor.

### The one move that unlocks the rest

Tell him early in the call that she has decided to rename. This costs nothing she has not already decided to spend, and it turns the conversation from "who owns this word" into "how can we help each other". Once the name is off the table, asking to list DMF's events and offering development help both land as gifts rather than as manoeuvres.

### Suggested flow (Danish, in Petya's voice)

Opening, about 30 seconds:
"Hej Finn, det er Petya. Tak fordi jeg måtte ringe. Jeg vil bare kort fortælle, hvad jeg laver, og så høre lidt om jeres planer."

Clearing the name question:
"Først det med navnet: Jeg har besluttet at skifte navn på min side. I har haft Vandrekalenderen siden 1974, og jeg vil hellere have et godt samarbejde med jer end et navn, der ligner jeres. Så det behøver vi ikke bruge mere tid på."

What the site actually is (this is where she differentiates without competing):
"Min side er ikke en kalender for ét forbund. Den samler vandreture fra alle arrangører i hele landet, både foreninger og private, i én kalender man kan filtrere på dato, sted og distance. Lige nu er der omkring 500 ture. Tanken er, at folk skal kunne finde en vandretur i deres område på søndag, uanset hvem der arrangerer den."

Their walks on the site (inform, don't ask; listing public event facts with a link is normal aggregator practice, so there is nothing to refuse):
"Ideen er at jeres vandringer skal også med i kalenderen, med tydelig angivelse af at det er DMF/IVV, og link direkte til jer, så folk ender hos jer. Sig endelig til, hvis I vil have det vist anderledes. Og hvis I på et tidspunkt får en bedre kilde end PDF'erne, for eksempel fra den nye Vandrekalenderen, vil jeg meget gerne hente derfra i stedet."

The offer:
"Du skrev, at der kommer en ny Vandrekalenderen. Jeg er udvikler, og jeg har allerede bygget noget, der ligner. Hvis det kunne være en hjælp, for eksempel med at få de gamle PDF-programmer over i et rigtigt format, vil jeg gerne kigge på det. Jeg søger også arbejde for tiden, så hvis I på et tidspunkt får brug for hjælp til udvikling, hører jeg gerne om det."

Questions to ask, pick the ones that fit the flow:
"Hvem bygger den nye Vandrekalenderen, er det jer selv eller et bureau?"
"Hvornår regner I med, den er klar?"
"Bliver vandredanmark.dk og Vandrekalenderen én side, eller to?"
"Hvordan får foreningerne i dag deres vandringer ind i kalenderen?"
"Er der andre i DMF jeg bør tale med om det tekniske?"

The referral (bring up last, only once the rest has landed; this is the biggest prize of the call, a link from an established Danish hiking organisation):
"Hvis I nogensinde får spørgsmål om vandreture, der ikke er jeres egne, må I meget gerne henvise til min side. Jeg viser alt, også jeres, og folk ender altid hos arrangøren." If he is open to it, suggest a concrete spot: a line on the "Øvrige vandringer" page saying "Se også Alle Vandreture for vandreture fra andre arrangører." Do not push if he is vague; put it in the follow-up email with the link ready to copy once the new domain is live.

Closing:
"Tak for snakken, Finn. Jeg sender dig en kort mail med det, vi har talt om, og med mit nye navn, når det er på plads."

### Things to avoid

Do not apologise for the domain more than once; she did nothing wrong and over-apologising invites him to treat it as a problem. Do not promise a date for the rename beyond "i løbet af efteråret". Do not offer to give him vandrekalender.dk on this call; if he asks, "det kan vi sagtens tale om, når mit nye navn er på plads" keeps the option open. Do not bring up Dansk Vandrelaug or Fodslaw as sources unless he does; DMF and DVL are separate organisations and it is not her place to compare them. Do not mention that Google ranks them ahead of her; irrelevant to him and slightly undermining to her.

### After the call

Send a short thank-you email the same day summarising any agreement (listing their walks, attribution, any technical help discussed). Then register the new domains, if not already done.

## 8. What a rename actually involves (preview, plain terms)

This is the map. The step-by-step guided execution comes in its own session once the name is registered. The whole thing is a weekend of careful work, not weeks, because the site is small and Petya already has staging, wp-cli and SSH.

1. **Register the new domain(s)** at the registrar and point them at the Nordicway server. In cPanel the new domain is added as an "addon" or "alias" domain on the same hosting account and an SSL certificate is issued for it (usually automatic, Let's Encrypt).

2. **Tell WordPress its new address.** WordPress stores its own address in two settings, `siteurl` and `home`, and also writes the full address into thousands of places inside the database (links in posts, image paths, plugin settings). The tool for this is `wp search-replace`, a wp-cli command that finds every occurrence of the old address and replaces it with the new one across all database tables, safely handling the way WordPress serialises data. Run it on staging first, check the site, then on production.

3. **Redirect the old domain to the new one.** A "301 redirect" is the server telling browsers and Google "this page has moved permanently, here is the new address". It is a few lines in the `.htaccess` file on the old domain, mapping every old URL to the same path on the new domain. This is what preserves the existing search ranking; Google transfers most of the equity to the new address over a few weeks.

4. **Update the things that know the domain by name.** Google OAuth (the "log in with Google" button) has a list of allowed redirect addresses in Google Cloud Console; the new domain must be added or the button breaks. Rank Math: organisation name and schema, sitemap regenerates itself. Polylang: nothing to change. GA4: update the data stream's website address. Any hard-coded domain in the theme, the social share image, the logo, and the SCSS build if it contains the name.

5. **Tell Google about the move.** Add the new domain as a property in Search Console, submit the new sitemap, and use the "Change of Address" tool on the old property, which formally tells Google the site has moved and speeds up the transfer.

6. **Email.** Create kontakt@allevandreture.dk, keep kontakt@vandrekalender.dk as a forward for at least a year, update the sending address in WordPress.

7. **Everything else.** Facebook page, Instagram, GitHub repository name (optional, the repo name does not affect the site), the local Docker environment, the wp-env sandbox, the project documents, and a short personal email to the two organisers who already signed up explaining the new name.
